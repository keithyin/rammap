diagonal_filter：对角线直方图 top-K anchor 过滤

挂在 anchor 构建之后、DP 链化之前 · 原型见 prototype/diag_topk.py · 本页数据由该原型导出（合成靶序列 100 kb，seed=0，k=15，w=5），链化为同一原型的 JS 移植

一、核心几何直觉

共线比对有一个刚性性质：所有真 anchor 落在同一条对角线附近。给每个 anchor 定义对角线坐标：

d = r − q  （query 位置已在 anchor 构建时按链方向镜像，正/负链公式相同）
  • read 相对 target 的 indel 让 d 沿链缓慢漂移，但漂移被 bw(500) 约束；
  • 噪声 anchor（重复 k-mer 的错位命中）的 d 均匀散布在整个值域 (−qlen, +tlen) 上；
  • 所以：真链 = 对角线上的峰，噪声 = 对角线背景。分桶计数后，真链就是直方图里拔尖的柱子。

直觉实验（文档实测）：最优链 238 个 anchor 的 d 全部落在 [−40, +36]，集中在 2 个 50 bp 桶；而全部 646 个正链 anchor 散布在几十个桶上，top-5 桶只覆盖 63%。

三、为什么能缓解：同时打掉两层乘子

链化工作量 ≈ anchor 密度（×3.3） × 每锚扫描步数（×3.5，skip 计数被稀释）≈ 11 倍。对角线过滤是唯一同时攻击两个乘子的手段：

乘子 ①：密度

示例 read 652 → 313 个 anchor（−52%）；61 条 read 合计 31,442 → 17,977（−43%）。进入 DP 窗口的候选直接变少。

乘子 ②：散布

被丢弃的正是 query 倒挂（MIN 制造者）与前驱稀疏（no-effect 制造者）的离群 anchor。留下的 anchor 方向一致、前驱互相链接，visited 命中率恢复 → skip-break 提前触发。实测每 anchor 扫描步数 88 → 29.8，几乎回到干净数据的 25 步水平。相乘后总扫描 57,500 → 9,337（−84%）。

在下面的演示里可以验证乘子 ②：拖动 B/K 观察「scan/anchor」一列——如果过滤只是线性少了一半 anchor，scan/anchor 应不变；实际它会一起下降。

实测对照：−f 0.01 只砍掉 32% anchor（只能动高频种子），对角线 K=3 砍掉 46% 且不伤真链。选择 read #47（重复区多对角线）可以直观看到：高频种子在重复区的多个真命中会形成多条对角线峰，top-K 把它们全部保留为次优链（MAPQ 来源）。

五、设计参数与失败模式

  • 桶宽 B（最敏感）：真链 d 随 indel 漂移（示例 read 1.7 kb 漂 76 bp，横跨 2 个桶）。B 太小 → 真链被拆进多个桶、部分桶落选 → 丢真 anchor。把 K 调到 1、B 调小，选 read #5，即可现场复现 recall 崩掉（0.97 → 0.40）。建议 B ≈ 50–100 bp 并随 bw 缩放，或保留峰桶 ±1 邻桶；真实 subread（10–15% 错误率）漂移更大，B 要相应加宽。
  • K 不能取 1：draft 里的重复区意味着 read 可能真有两个比对位点，次优链是 MAPQ（s2 tag）的来源，全杀会把重复区 MAPQ 虚抬到 60。更稳健的是覆盖率自适应：按计数降序累加桶，直到覆盖该链位 anchor 的 ~80% 或计数低于阈值。
  • 失败模式兜底：read 不比对 → 峰桶全是噪声，过滤无益也无害；read 有大缺失（对角线跳变 > B）→ 真链横跨多个桶，各桶有人气都会入选——这正是用「直方图」而不是「单一 d̂ 估计」的好处；防误杀兜底：过滤后最优链分数骤降（< 原值 60%）→ 用未过滤 anchor 重链化（可复用 rammap 已有的 high-occ re-chain 机制）。
  • 为什么不是 per-seed topN：按 ref 位置取前 N（N=2）最优链掉到 937/205——种子的真命中不一定排在 ref 位置靠前的 N 个里。对角线是唯一与「正确性」相关且不依赖任何先验偏移量的排序信号（|r−q| 版本内嵌了 offset≈0 假设，只在 target≈read 长度时成立）。
